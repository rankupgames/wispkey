# Windows receiver-enabled test artifact

This is a staging bundle, not an installer or a release. It contains a Windows x64 CLI and browser native host built with `--no-default-features --features experimental-browser-receiver`, matching unpacked Chromium/Firefox extensions, the existing Windows registration script, and source/hash metadata. Default shipping releases remain unchanged.

The experimental feature enables the local receiver library and its native release guard. It adds no network listener, receiver CLI command, device enrollment or trust configuration. Merely extracting this bundle cannot activate a receiver. Native owner approval is still required for fills; fill completion does not mean form submission or authentication.

Do not run the registration script, add this directory to PATH, replace installed binaries, select a real vault, or install the extension before a separate reviewed owner setup decision. The bundled registration script is unchanged and defaults to a source-checkout path; any future approved use must supply an explicit `-HostPath` to the bundle's native host. Windows Hello, the intended interactive OS account and human-controlled browser profile have not been verified by CI. A profile label alone does not isolate secrets from arbitrary code running as the same OS user.

The workflow builds at an immutable checkout, verifies Cargo's compiler-artifact feature records, checks for the feature-specific native-host prompt text, and runs receiver/default-off source tests. A separate Windows job downloads the archive, validates its exact paths and hashes, extracts it with `Expand-Archive`, and runs CLI help/version, rejection of nonexistent receiver activation, and native-host denial against a fresh empty scratch vault. It never registers the host or prompts for native presence. These checks prove packaging and fail-closed startup, not installation or live browser acceptance.

`BUILD.json` records the source commit, target, exact features, lockfile hash and contained-file hashes. `SHA256SUMS.txt` beside the final ZIP covers the ZIP and `smoke-report.json`. Successful main-branch builds receive GitHub build-provenance attestations; pull-request artifacts are validation candidates without that attestation. Final artifact retention is seven days. Verify the actual artifact metadata for its expiration and verify attestation/source/hash before transfer. Keep the source commit and feature manifest together; version `0.4.0` alone does not identify this build.
